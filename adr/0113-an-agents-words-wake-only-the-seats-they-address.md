## The decision

**A message wakes a seat for a standing arrangement only when it asks something and is addressed to nobody in particular.** Following a room, following a thread, having spoken in a thread, being the other side of a direct conversation or the author of the thread are standing arrangements. They wake a seat for a person's message that names nobody, and for an agent's message that says it asks something, and never otherwise.

**An agent's words wake another agent only when they ask, assign, or answer that agent's open ask.** Every tool that posts an agent's words, the chat posting tools, `comment_on_work_item` and `comment_on_page`, requires it to state `asks`: true when the words ask someone for an answer or an action, and then the seats they name, or the other side of a direct conversation, are woken and obliged to answer. A tracker comment's `ask` asks by itself. With `asks: false`, an @-mention of an agent is a reference: the named agent is told, in its inbox and in the room or on the item, and is not woken by it, while a person it names is addressed as before. Such words wake only the seat whose open question they answer (`answer` in chat, `answered` in the tracker) and the seats with a stake in their thread. A page has no answer record, so its stake is an agent's last word in a comment's thread: while its newest comment there asks (`asks: true`), it is woken by any reply in that thread by somebody else, whatever the reply names, and its own later comment that asks nothing ("thanks") ends the stake, so an exchange ends at the first acknowledgement. The co-asker exception holds there too, and a top-level comment that names an agent whose open ask is addressed to its author wakes that agent as a reply in the thread would. A removed comment asks nothing, and an edit keeps the statement its comment was posted with, as a chat edit does. An assignment wakes its assignee as before. An asking message gives each seat it asked a receipt, so its answer wakes the asker; a seat it woke only for its own stake or for an answer was not asked. A top-level post in a named room answers the newest open top-level ask each agent holds of its author there, every asker's alike, and an older one stays open for a later post.

**A message that names somebody is addressed to them.** A person's message that @-mentions a seat, and anybody's that asks one or answers one, wakes the seats it names, the asker it answers and, in a direct conversation, the other side when it asks, and no seat for a standing arrangement. People are never woken and still see everything, in the room and in their inbox, exactly as before.

**One rule for a stake, in every domain.** A participant with a stake in a thread, an open ask it made or one made of it that it still owes, is woken by any reply in that thread by somebody else, whatever the reply names (`awaiting` and `owing` in chat, `thread` in the tracker), except a reply by a co-asker: a seat whose only stake is awaiting the same addressee does not wake another seat awaiting it. A person's own open ask is a stake, so a person awaiting that addressee is a co-asker too: in the tracker the person's ask, in chat the person's message, which asks every seat it reached. Everybody else follows the rules above.

Every decision is made from structured facts the record carries (the author's kind, the mentions, the `asks` statement, the ask and answer records and the open receipts), never from the prose. Every agent comment carries its statement, true or false, at a version of its own (tracker 5, pages 3; chat decides at write and carries its recipients at 2), so an older build retains it rather than route it the old way, and a record with no statement, a person's or an older build's, routes as it always did on every node. The seats a rule held back ride the chat record as `held`, which the parser logs as `chat_wakes_held`.

## Why the obvious alternative is wrong

**The obvious alternative is to tell agents not to acknowledge**, in the prompt. The prompt already said an unaddressed wake may end in silence, and the measured loop ran anyway: a direct message and a mention oblige an answer through the delivery gate, so an agent acknowledged into a direct conversation or named in an acknowledgement had to reply, and its reply obliged the other side. Text cannot release an obligation the routing imposes.

**Waking the named agent while obliging nothing** (`named`) was this record's first answer, and it was wrong: a woken model that was named replies, and names the agent that named it, so a mention without an ask kept the loop the rule was written to stop, and on work items, which carried no `asks` statement, every mention still obliged an answer. A reference that wakes nobody is what an acknowledgement is.

**Reading the prose for a question mark or a thank-you** is the other obvious answer. A model's "Done, thanks" and "Done, can you check?" differ in a way only the model knows, and a heuristic that guesses wrong either drops a question or keeps the loop. The agent knows whether it is asking, so it says so, and the engine records it.

## What this does not decide

It does not change who is told: every candidate a Worklet change concerns still gets its inbox notice, every chat message stays in its room, and a page comment's mention still makes the named seat follow the page. It does not change how a page save wakes the page's followers. It does not change a person's routing when the person names nobody. It does not change the vendor chat surfaces (Mattermost and Slack): an agent posts there through the vendor's own message, which carries no `asks` statement for the engine to read, so their routing stays the vendor targeting it was.
