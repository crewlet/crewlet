# ADR-0112: An idle agent seat is handed its next ready item, once per item version

- **Status:** accepted
- **Authority:** `internal/pickup`
- **Enforced-by:** `internal/pickup.TestAPickupIsKeyedOnTheItemsVersionBySomebodyElse`, `internal/worklet.TestAnItemWaitsUntilItsDateAndSaysWhy`, `internal/worklet.TestAReviewIsReadyForTheSeatThatHoldsIt`, `internal/worklet.TestANoAskCommentOrWatcherChangeDoesNotReArmThePickup`, `internal/pickup.TestASeatThatIsNotIdleIsHandedNothing`, `internal/worklet.TestReadyWorkComesStartedFirstThenTheListThenTheQueue`, `internal/worklet.TestReadyWorkLeavesOutWhatCannotStartNow`, `internal/pickup.TestAnIdleSeatIsHandedItsReadyItemOnce`, `internal/pickup.TestAPickupThatCannotBeSentIsTriedAgain`, `internal/pickup.TestADeclinedItemGivesWayToTheNext`, `internal/pickup.TestThePickupReadsPastTheFirstPageAndRemembersAnAllOfferedSet`, `internal/engine.TestAPickupIsWorkedForWhomItsItemIsFor`, `internal/agent/builtin.TestAPickupTurnIsHeldAsTheAssignmentTurnIs`, `internal/pickup.TestProgressHandsAStartedItemBackOncePerCooldown`, `internal/pickup.TestARequesterNoLongerHeldIsWorkedForAsAStranger`, `internal/worklet.TestReadyWorkSaysWhomTheWorkIsFor`, `internal/worklet.TestAPickupReadsTheAssignmentWhateverKindItsRecordEndsWith`, `internal/worklet.TestReadyWorkTimesAndProgressFollowTheKey`, `internal/worklet.TestAHistoryRowKeepsAppsOnlyFromTheVersionThatSaysSo`, `internal/engine.TestAPickupIsAWakeOfItsOwnType`, `internal/pickup.TestACoolingItemGivesWayToTheNext`, `internal/pickup.TestAPassTakesTheSeatsCooldownOnce`, `internal/sandbox.TestASeatWaitingPastThePauseTTLIsHandedWork`
- **Measured:** on a company running this engine, over about five hours: 200 turns, a median of 20 seconds and none over five minutes, while 28 items assigned to agents, none of them waiting on an open blocker, sat untouched for 20 to 260 hours, and several items in progress had no run behind them.
- **Cost-when-tried:** the workaround that company ran, a schedule per role whose task text said "pick up your next ready item", fired on a clock whether or not the seat was busy, could not tell which item it meant, and woke a seat with nothing ready as often as one with ten.
- **Tag-status:** unreleased

## The decision

**The holder of an agent seat derives one wake for it, a pickup, when the seat is idle and holds ready work.** Every node that publishes runs a loop over the agent seats it holds, once a minute. A seat is idle when no turn of it is dispatching, no executor run holds it or waits on a person's answer with its box still paused (within its pause TTL: past it the run still takes its answer, but keeps the seat from nothing), nothing waits in its inbox, it is not paused, no budget or provider park holds it, no budget window or provider limit would refuse its next launch, and the node is neither shedding nor draining, and all of that held on the previous pass too. An idle seat is handed its first ready item: work it already started, then the reviews it holds, then its priority list in its lead's order, then the rest by priority and due date. Ready is assigned to the seat, `in_progress` or `todo`, waiting on no open blocker, past its start date, and not held on a question the seat itself asked on it; an item `in_review` is ready on the same terms for the seat that holds it when somebody else moved it into review (or filed it there), so a reviewer handed a review takes it up, and a seat never reviews what it submitted itself.

**A pickup is made once per (seat, item, the last change to the item that would have woken the seat, status, for started work the seat's own last progress on it other than a comment, and the start date it waited until).** That change is read off the seat's own notice of it, which records whether the notifier woke the seat (`starts_turn`), so the pickup and the wake decide by one rule: another agent's words that ask nothing, or a watcher added, tell the seat and hand it nothing again. The applier reads only the record, so it counts every seat as employed: where the parser falls back to a lead because the assignee's seat is gone, the notice rows can say the lead was not woken. A record keeps the decision only from record version 7, marked where it tells somebody it does not wake; every older or unmarked record reads as waking its recipients, so every node writes the same rows. Its event id is derived from that key, so the fleet's completion ledger refuses a pickup the seat already had its turn on, whichever node holds the seat and across restarts, for the ledger's retention of seven days. A fleet claim on the same key keeps two nodes that both believe they hold the seat from publishing it twice. A seat that declines an item, records a blocker on it or comments on it is not handed it again until a change that would wake it lands, or until the date it set the item aside until (`wait_until`) comes: a start date is part of the key only on an item that has one, so the key of every other item is the one older builds derive; started work the seat makes progress on is handed back when the seat is idle again, at most once per cooldown. Progress is a change to one of the item's fields: a turn that changed nothing, or wrote a value already there, does not re-arm it. The ready order is read page by page, so item twenty-one onwards is offered once the first twenty were, and a seat whose whole ready set was already handed over costs no ledger read until the set changes.

**The cooldown spaces declines and hand-backs, not new work.** A fleet claim on the seat, `scheduling.work_pickup.cooldown_seconds`, is taken only when a pickup passes over an item the seat was already handed and left unchanged, so a seat that finishes items is handed the next at once. A second claim, on the item without the seat's own progress, spaces the hand-backs of one started item by the same cooldown, so a turn that answers every pickup with a write cannot loop; a pass that finds an item cooling hands over the next ready item instead.

**The pickup's turn works for whom the item is for (ADR-0109).** The wake carries the writer of the item's last assignment by somebody else, else the writer of its creation, both read from the item's history rows and never from the reporter field, which a writer sets to anybody. A credential carries the apps it wrote under, re-narrowed on the node running the turn, so the turn is held exactly as the assignment's own turn was. A history row keeps a writer's apps only from a record at version 4 or later that says it kept them, so a row an older build wrote carries none and its credential holds no app. A seat the organisation no longer holds is worked for as a stranger.

**On by default**, with a ten-minute cooldown (`scheduling.work_pickup`). The wake is a type of its own, `work_pickup`, so a build that does not know it never reads it as a schedule's fire with an empty task. It carries the item, its status, its key and why it was chosen, stamped with the instant of the change its key names and filed under the item's own conversation, so the turn continues the item's session; its brief names the item and the four honest ways to answer it. `crewlet.work.pickups{outcome}` and the `work_pickup_woken` and `work_pickup_skipped` lines are what an operator reads.

## Why the obvious alternative is wrong

**The obvious alternative is to wake the assignee again from the change feed**, on a timer per assignment, as [ADR-0012](0012-a-wake-is-derived-not-published.md) derives every other wake from a committed record. It is wrong because the record that should cause the wake does not exist: what went wrong was that the seat's turn did not start the work, and nothing is written when a turn decides to do something else. A timer per item wakes a busy seat as readily as an idle one, and a seat with ten ready items ten times.

**Re-waking until the item moves** is the other half of the obvious answer, and it is the loop this replaces: a seat that has a reason not to start an item says so every time it is asked. Keying on the last change that would have woken the seat makes "no" an answer that holds until the facts change, and makes the seat's own comment on the item not count as a change.

## What this does not decide

It does not decide what a seat does with the item; the brief names the choices and the delivery obligation of a `work_pickup` holds the turn to a tool. It does not change how an assignment, a status change or the unblocked repair wakes a seat: those still wake from the change feed, and the pickup is the backstop for the turn that did not act on them. It does not cover a seat on a vendor tracker, which the engine does not read for ready work. It does not decide whom work a seat filed for itself is for: such an item names no other writer, so its pickup is the seat's own work, and whom the filing turn worked for is the write edge ADR-0109 leaves to a record that carries it.

An older build carries a `work_pickup` losslessly (ADR-0006) and, like any wake type it does not know, runs it as a turn whose ask is the type's name, for the seat itself. Only the node holding a seat publishes its pickup, so this reaches an older build only for a seat that moves to one during a rolling upgrade. The window is minutes, no tag has shipped the earlier rule, and it is accepted as ADR-0109's was.

## Amendment: an assignment is a row that moved the assignee

**The item's last assignment by somebody else is its newest history row that moved its assignee, whatever kind the row's record ended with**, written by anybody but the seat and the engine's own duties. A record carries one kind, so a write that hands an item over and moves another field in the same call, "assign it to you and set it to todo" above all, is filed under the other change's kind, and a pickup that read only `assignee` rows worked that hand-off for whoever assigned the item before it (#930). An assignment to the seat that already holds the item moves nothing and is no assignment, so another agent's reassertion leaves whom the work is for where it was. An item filed already assigned records the assignee on its creation row too; that row is its oldest, so any later assignment outranks it, and where it is the only one it names the writer that filed the item, as the creation's own arm does. The seat's own rows stay out, a take included.
