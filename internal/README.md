# The packages under `internal/`

**Every package states its own rationale in its package doc.** `go doc ./internal/coord` is the authority on coordination, not this file. What follows is a map, so you know which doc to read: one line per package, saying what it is for. A row that still runs longer holds decisions its package doc has not absorbed yet (#1474 folds them in package by package); read it with the doc, and record a new decision in the doc, never here. A row may not grow (`internal/commentgate`), and a new package gets a one-line row.

| `sandbox` | The executor runtime: every agent seat's executor is its harness's own run in a box. A run is DETACHED: the launch starts it, the turn parks, and the engine resumes the same turn with the run's report, minutes later, possibly after a restart, possibly on another node. Nothing parks a goroutine on a running job. EACH COLLECTED LAUNCH IS A RECORD OF ITS OWN (`types.ExecutorCollected`, `Coordinator.publishCollected`) (its tokens, its harness's turns and price, its report and transcript) published ONCE per launch with its charge (`LaunchRecord.Published`), and NO PHASE: the work of the `execute` round that launched it, which every spend reader files it under. A run ASKS a person through `ask_and_wait` on its bridge (ADR-0068), in the shape of a `decision.Decision` (ask.go): the tool validates the whole ask, `PendingStore.RecordAsk` writes it onto the job's row only while that job is running, and the collection parks on what the row holds, never on a file in the box. A run that asks a person something frees the seat, and the answer CARRIES THE RUN ON (`LaunchRequest.Continue`): the same round relaunched, continuing the turn's kept session in whatever box it gets (below), else the asking job's own session in the box it kept where the relaunch reuses that box (`PriorBox.ContinuesIn` and `Coordinator.hostsPrior`: the same harness, the same cell, a box this node drives), or afresh from its pushed branch otherwise. HOW THE JOB'S HARNESS ENDED IS ON THE JOB'S OWN RECORD (harnessend.go, `LaunchRecord.HarnessEnd`, `PendingStore.MarkHarnessEnd`), since the copy a relaunch carrying the round on in the job's box continues is described by no capture: the read that collects a job writes `own_run` or `cut_off` by `readCapture`'s line, whether or not it takes or keeps a capture — after its take, in the room the read leaves the take's own records, which counts its crossing as the read's budget does (`Coordinator.recordsBy`, `Coordinator.takeRecordsRoom`, `Coordinator.recordContext`) — cut off once cut off for the job (`HarnessEnd.after`), and carries it back with the result for the claim it collects for (`Result.HarnessEnd`, merged in `collectClaimed`); an empty record is never read as an own run, and a read made while the run's ending is decided records nothing. AND WHAT THE COPY'S NEWEST REQUEST CARRIED, in that read's one write (`LaunchRecord.Context`, `session_context`; `MarkHarnessEnd` handed an `EndRead`, landing where the end or the measure changes) and with no box read of its own (`Result.LastRequest`, set by `Collect` after its result block): Claude Code's off the run's event stream, its newest main-thread assistant line (`parent_tool_use_id` present and null) and that line's usage read by the layer's one rule (`readUsage`), a usage that does not read, or a line past the bound or cut short, clearing the figure; OpenCode's off the session's own message list, which the run's script asks of its server once the session is exported, never on an end request, one assistant message a page by the cursor read as text anchored at the answer's end (`openCodeContext`, at most `openCodeContextPages`, 6, and `openCodeContextBytes`, 1 MiB; like EVERY call an OpenCode run's script makes to its own server, each page BOUNDED by one helper of the script's, `openCodeBounded` (`bounded`/`unbound`: the call a grandchild whose end is a status file its subshell writes, never `kill -0`; ended `SIGTERM` first and `SIGKILL` past `JobStopGrace`, and reaped; ended at an end request too where it comes before the run), one constant a kind of call (`openCodeCallWait`, 10 s, a call whose answer is a few KiB; `openCodeSessionCallWait`, 30 s, one whose answer holds the session or a message of it; each set from the slowest measured on OpenCode 2 with a box's cores kept busy), each past its bound going the way a call to a server that is gone goes, and the calls on an end request's way out held under `JobEndWait` (`openCodeEndPath`)), the first settled message that measured a prompt being the figure (`measuredPrompt`, the rule an export's meter reads by too); `harness_context_unmeasured` says why where there is none. A job that made no request of its own carries the figure along its copy's lineage and says where it came from (`MeasureSource`; `continuedLaunch.measure`, written by the attach from `BoxRef.Context`, the in-place copy's read by the reset into `PriorBox.Context`), and `collectClaimed` merges the read's onto the claim by the record's rule (`LaunchRecord.measured`). SO ARE THE READS THE JOB'S BRIEF LEFT OUT (`BriefTold`, `LaunchRecord.BriefOmitted` and, beside a brief that continues a session, `FreshOmitted`), by their places in the round's log, written with `Brief` by the attach that names the job's command only where the launch carries a round on (a send-back's round restarts its log), each at most `MaxBridgeCalls` and refused past it before the row is written, and read by the brief the job's run read (`LaunchRecord.OmittedCalls`: by `Brief`, then `SessionStart`, the union where the box never said); a capture placed by its own read states them (`SessionCapture.Omitted`, held by `Bounded`, copied with the point by `placeAtNewest`), since a session holds what its brief told and never what its read cap left out. The answer is SEALED on the run's row under the fleet keyring (`seat.run.answer`, answerseal.go), bound to the run, its question and its deliveries, and its words and answerer exist there only inside the seal: every reader opens it first, one under a key the node does not hold waits recorded and owed, and one that does not open is handed to no turn, attributed to nobody and let go of. Every HOST-SIDE ACCESS to a local box's files (read, write, directory made, file removed) goes through its home (or its records) opened as an `os.Root` (`boxLayout.openHome`), by a name relative to it, every directory on the way opened as a directory (a pipe there refused at once, never waited on), never a path checked and then opened: a directory the box made a link out of the home is refused at the access, whenever it was put there, and `hostbox.SafeJoin` only words the refusal (`directBox.explain`). A WRITE REPLACES THE FILE WHOLE (`replaceIn`, over `hostbox.ReplaceFileIn`): staged beside it under a fresh name, synced and renamed over it, so a reader in the box (the git credential helper reading the token file the poll rewrites under a running job) finds the old file or the new one, never one truncated and half refilled, and the rename writes through no link or other name at the path; only a regular file is replaced, anything else there is refused and left as the box made it, and nothing staged outlives a failed write. An E2B box's write is envd's upload under a fresh name beside the path and its filesystem `Move` over it (`envdClient.writeFile`), because envd writes an upload in place.
