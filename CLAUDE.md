# Crewlet — Project Conventions

Crewlet is a Go engine for orchestrating hierarchically organized AI agent companies. Every session and agent loads this file, so it holds only what any change needs. Area rules in `.claude/rules/` load with the files they cover, and procedures in `.claude/skills/` load when used ([Where the Rest Lives](#where-the-rest-lives)). `internal/docsgate` holds this file to its budget.

## Where to Look
- **`docs/` is the source of truth** for how the system should work. `docs/index.md` lists every page and is the site's navigation. Before changing a subsystem, read its page under `docs/concepts/` (`overview.md`: the vision, principles and architecture).
- **`internal/README.md` maps every package**, one line each. A package's decisions live in its package doc (`go doc ./internal/<pkg>`): read it before changing the package, and record decisions there, never in the map. Until #1474 folds a package's row into its doc, read the row too. A row may not grow (`internal/commentgate`); a new package gets a one-line row.
- **`adr/`** holds decisions that bind more than one package. Each names an Authority it may not restate and an Enforced-by (a test, a compile error or `nothing`); `internal/adr` checks both ways.

## This Is a Public, Source-Available Repository
Crewlet is source-available under the Elastic License 2.0 (`LICENSE`, with its `NOTICE`: any use but providing it to others as a hosted or managed service) and developed in the open at `github.com/crewlet/crewlet`. A `v*` tag ships signed binaries and a container image; `ghcr.io/crewlet/crewlet:main`, rebuilt on every push to `main`, is not a release. `docs/` is served at docs.crewlet.ai. Everything committed stays public (history keeps what a later commit deletes), so write for a stranger who will read, run and depend on it.
- **Never commit a secret**: no real API key, token, PAT, webhook secret, private hostname, internal URL, or customer or employee name, in code, tests, docs, examples, fixtures or commit messages. Examples use `${VAR}` and placeholders (`example.com`, `U0FOUNDER`, `sk-ant-...`). A pushed credential is compromised and must be **rotated**; deleting it in a later commit fixes nothing.
- **Commit subjects are semantic**: `type(scope): summary`, imperative, lowercase, no trailing period, ≤72 chars. Type is `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `ci`, `build`, `chore` or `revert`. Scope is the package directory under `internal/`, `dashboard` (`dashboard/`, `static/dashboard/`), `cli` (`cmd/crewlet/`), or else the area (`docs`, `deps`, `examples`, `schema`, `scripts`, the workflow's name for `ci`). An incidental fix or tuning the change needed gets its own commit and scope. A pull request lands as a squash or a merge commit, so its title takes the same form. `CONTRIBUTING.md` has the full rules.
- **Every commit is signed off** (`git commit -s`, certifying `DCO`). `scripts/check-signoff.sh` checks that a pull request's own commits carry the trailer, merge commits exempt, in `make check` and ci.yml's `sign-off` job. Repair a missing one by rewriting the commit (`git commit --amend -s --no-edit` or `git rebase --signoff origin/main`).
- **The pull request title is the release note**: each Release body is generated from the titles merged since the previous tag (grouped by `.github/release.yml`; there is no `CHANGELOG.md`), so a user-visible change's title reads as a release note for someone running Crewlet.
- **The root-level files are canonical for process**: `CONTRIBUTING.md`, `RELEASING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `DCO` (upstream text, never edited), `LICENSE` (likewise) and `NOTICE`. This file and `.claude/` may not contradict them; a rule changed here changes there in the same commit.
- **Use the repository's templates**: `.github/pull_request_template.md`, `.github/ISSUE_TEMPLATE/`.
- **Third-party code must be compatible with the project's license (permissive licenses such as MIT, BSD and Apache-2.0) and attributed.** Source files carry no license headers; don't add them.
- **Security issues never go in a public issue or pull request description**: see `SECURITY.md`.

## No Band-Aids — Always Do the Proper Fix
Find the actual problem and fix it at its source, completely: no band-aid, workaround, partial fix or hack that "works for now". **A fix's cost is never a factor**: its scope matches the problem's, whether that is one line or a 2,000-line refactor across 50 files. When suggesting fixes, lead with the proper one whatever its size; never pre-filter on effort, time or scope, or offer a cheaper "quick" option as the default.
- **No workarounds**: no special case, flag or conditional around a broken abstraction; fix the abstraction. A compatibility shim (an alias, a both-spellings fallback, an adapter) is the same move, and an unreleased surface has nobody to be compatible with ("Breaking Changes Are Free Until a Tag Ships Them").
- **Nothing temporary**: every change is one you would maintain indefinitely. Refactor rather than bolt onto a broken foundation.
- **Update everything**: the fix includes all tests, docs and dependent code.

## Fix the Bugs That Affect Your Work — Open an Issue for Unrelated Ones
For each bug you notice, ask: **does it affect what you are implementing?** It does when your change depends on it, when it is in the code or text you are changing, when your change makes it worse or newly reachable, when it is another copy of the defect you are fixing, or when it keeps your change from passing a test or gate; that it was broken before you came does not make it unrelated. Then fix it in this change, properly (root cause, tests, docs). If it is **totally unrelated**, leave its code alone and open an issue (the `file-issue` skill): an unrelated fix folded in is a second change nobody reviewed, reverted with the first. Doing neither is never an option.
- **"Totally unrelated" is the bar, not the default**: if you cannot show that none of those holds, fix it. An issue never replaces a fix your change needs.
- **A security bug never goes public**: anything you believe is exploitable, related or not, goes through `SECURITY.md`'s private reporting, never an issue, commit message or pull request description. If you cannot file that report yourself, tell the user and let them decide how the fix lands.
- **Surface what you fixed and filed**: every incidental fix in your summary and commit message (its own commit where that keeps history clean), and a link to every issue you opened or added to in your summary and the pull request description. If you could not open one, give the user its title and body.
- **A needed fix too big for this change** (its own coordinated effort, a risky redesign) is neither dropped nor filed as unrelated: fix what you safely can and raise the rest with the user.

## Tuning Knobs Are Findings Too — Don't Defer Them Either
A plainly wrong value is a finding like a bug: a magic number, an arbitrary timeout, retry count, backoff, batch size, poll interval, cache TTL, concurrency cap, page or buffer size, rate limit, log level, flag default, temperature or model choice, a baked-in value that should be config, or config that should be a constant. Its right value is often a judgment call: make it, or escalate it with a concrete recommendation, but never walk past it.
- **It goes where a bug would**: a knob your change depends on, touches or makes worse is tuned in this change; one in code you don't touch gets an issue naming the value you would set and why.
- **Tune to the value you can defend** from the code, the data and the surrounding behaviour, never a placeholder or a "configurable later" hook. Expose or collapse deliberately: a value callers genuinely need to vary becomes config; one with no honest reason to differ becomes a constant.
- **Record why this value** where the next reader sees it (the config doc, a comment at the definition, the commit message), tied to something real: a dependency's p99, a page-size limit, the SLA, a memory budget.
- **Surface what you tuned**: each knob changed, exposed or collapsed, with its old and new value and the reason, in your summary and commit message; link each knob issue you filed.
- **When the value needs production data, a benchmark you can't run or a product decision**, make your best-justified call, mark it, and raise it with the user with a recommendation and the tradeoff. An issue for a knob you did not tune carries the same.

## No Deferred Work — Always Deliver the Clean Implementation
Finish what you start, completely and cleanly, until a reader of the diff would call the task done. A large task is a reason to deliver all of it; a planned series of pull requests (below) is how it gets finished, never a way to defer part.
- **Decide and deliver** end to end: no half-built parallel path, no decision left for later.
- **No `TODO`, `FIXME`, `XXX`, stub, placeholder, `raise NotImplementedError`, "fix later" comment or empty body pretending to be done**: what is in the diff is finished, in every pull request of a series.
- **No follow-up ticket or "phase 2" for the current scope**: it ships in this change or in a later piece its series' tracking issue already lists. An issue is for what lies outside the task. A series is planned up front and runs until its last piece lands.
- **No silent narrowing of scope**: deliver the full scope, or raise the cut with the user first.
- **Tests, docs and migrations are included**: a feature without tests or docs is not delivered.

## Split a Large Change into a Series of Mergeable Pull Requests
Before writing code, judge from the planned diff whether to split. Run it as a series (the `pr-series` skill) only when one pull request would be hard to review or would drift from `main` while open, AND it has seams where `main` can take a part alone (a refactor the feature needs, a new package before its wiring, a migration before its readers, one subsystem before the next); otherwise it is one pull request. Tell the user which you chose and why. A piece need not work alone, but `main` must be able to take it as it is: finished, passing every gate, breaking nothing, nothing half-wired. Never open a pull request against another pull request's branch: target `main` and say `Builds on #N`.

## Breaking Changes Are Free Until a Tag Ships Them
A `v*` tag is the only compatibility boundary; a surface no tag has shipped has nobody behind it. **Change it outright** (rename the field, reshape the struct, drop the flag, move the route), with no compatibility path (no alias, both-spellings reader, fallback, adapter, `V2` type or vestigial flag) and no breaking-change ceremony (no `!`, no `BREAKING CHANGE:` footer).
- **Establish what has shipped; never remember it**: `git tag --merged`, and `git log <newest tag>..HEAD -- <path>`. Today the only release, `v0.1.0`, is the initial commit, which holds no `.go` file, so nothing in this tree has shipped; re-run the check rather than trust this line.
- **A free break is still complete**: the rename lands everywhere in the same change (`docs/`, `examples/`, `skills/`, the dashboard, tests, package docs), `schema/` is regenerated, and a grep finds the old name nowhere.
- **Nothing an older UNRELEASED build wrote is read, migrated, swept or tolerated**, and code that exists only for one is deleted. Two exceptions: an applied migration is history, not source (`schema_migrations` keys on the filename), so reshape with a new numbered migration under `internal/store/schema/`; and this build must be a good OLDER peer to the next one, since a rolling upgrade mixes builds, so the forward mechanisms stay (`.claude/rules/compatibility.md` lists them).
- **Once a tag ships a surface**, breaking it takes `!` and a `BREAKING CHANGE:` footer naming what an operator must change, its pull request title says so, and while the major is 0 the minor number moves. `CONTRIBUTING.md` and `RELEASING.md` carry the whole rule; change all three together.

## Code Conventions
- **Interfaces are defined by the consumer**, in the calling package, kept to what it needs; a provider exports a concrete type, and there is no `interfaces.go`. Accept interfaces, return structs.
- **`context.Context` first, always**, threaded, never stored in a struct. A rollback or a teardown takes `context.WithoutCancel`: the failure it is undoing is often the cancellation itself, and a cleanup that inherits a dead context does nothing at all.
- **Zero values must be meaningful, or the type must refuse them**: a config field whose zero value is a valid setting needs a pointer or an explicit `Unset` sentinel.
- **Errors wrap with `%w`** and say what to do: an error a person reads names the field, file or variable to change. Sentinels are `errors.Is`-comparable; typed errors carry the identifier the caller needs.
- **A field holding words somebody else wrote is declared on the field**, as a credential's `secret:"true"` is: `untrusted:"fence"` for words at length (a body, comment, message, excerpt), `untrusted:"name"` for a title, name or label (`provenance.FieldTag`). The agent runtime's read tools refuse a declared field they neither fence nor name the writers of, and `agent/builtin`'s sweep (`TestEveryToolThatHandsOverSomebodysWordsIsFenced`) finds from the declarations which tools hand such words to a model, so a new read type carrying somebody's words declares them or escapes the fence (ADR-0040; `provenance.TestEveryDeclaredFieldHoldsText` holds every tag to those two kinds, on a type that holds text).
- **Every piece of state answers "who has to agree on it?"** before it is written. This node alone: the node's own database file. Every data node, identically, from an ordered log: the replicated estate, which ONLY a state log's applier writes. The whole company, now: the coordination store. Whichever node holds a seat, current value only: a compacted changelog (ADR-0014). A replicated row names it and the fleet's one shared store keeps its bytes: the object store (ADR-0026); a table that names an object is declared in `internal/objstore/references`, or the collector deletes its files. The stream is the write-ahead log and the SQL estate is derived, never the reverse (ADR-0002, 0003, 0004); `internal/store`'s estate gates refuse a table that skips the question.
- **A three-valued answer is `(value, error)`**, never a bool: "held", "definitively not held" and "the store could not be reached" are three facts (`internal/coord`).
- **IDs are `uuid.UUID`**, timestamps `time.Time` in UTC, durations `time.Duration`; a config field holding seconds is named `…Seconds` and converted once, at the edge.
- **Enums are a named string type** with typed constants and a `Valid()` method, so an unknown value off the wire is a value, not a panic.
- **Concurrency**: a goroutine's lifetime belongs to whoever started it, and every one has a way to stop. Channels for handoff, a mutex for state; `sync.OnceValue` over a `sync.Once` plus a variable. Everything runs under `-race`.
- **Comments explain WHY, briefly**: the decision, and why the obvious alternative is wrong. A comment block outside a package doc stays within 12 lines (`internal/commentgate`, whose inventory of older code only shrinks). The full argument is written once, in the package doc (within 20 KB) or an ADR when it binds more than one package, and the comment points there.

## Tech Stack
- **Go 1.27+, pure Go**: the module pins its toolchain (`GOTOOLCHAIN=auto` fetches it), and `CGO_ENABLED=0` builds every release target. **The standard library first** (`net/http`, `log/slog`, `context`, `encoding/json`): a dependency must earn its place against `std`.
- **Turso** (`turso.tech/database/tursogo`) is the embedded store and the ONLY driver; **NATS JetStream** is the event stream and the ONLY broker. No second driver, no Pulsar backend, no setting to select one (`.claude/rules/build-and-release.md`, `.claude/rules/broker.md`).
- **Harnesses are the only LLM backend**: every model call runs a vendor's own harness as a subprocess (Claude Code, Codex, OpenCode and others). There is no HTTP client to a model vendor and none is added (`docs/concepts/llm-backends.md`, `.claude/rules/harnesses.md`).
- **Other dependencies, each for its job only**: `github.com/modelcontextprotocol/go-sdk` for MCP client and server; OpenTelemetry (`go.opentelemetry.io/otel`, the OTLP trace exporters) for tracing, configured from the standard `OTEL_*` environment, not Tier A, the provider always installed and only the exporter conditional, because a trace id is an event-store column first; `github.com/openai/openai-go` for embeddings (`providers.embeddings`); official vendor SDKs for integrations where one exists, else a thin typed client (Mattermost, GitLab, Confluence); `github.com/aws/aws-sdk-go-v2` for the object store's `s3` backend and the AWS integration's IAM and STS calls, its HTTP through `httpx` (`internal/sigv4` signs Roles Anywhere's CreateSession and AWS's MCP Server, which the SDK doesn't cover); `gopkg.in/yaml.v3` for config; `github.com/ebitengine/purego` to load dictation's recognizer (sherpa-onnx, fetched per platform, `internal/speech`) without cgo.
- **Gitlet runs real upstream git** (≥ 2.55 on a Gitlet node, ≥ 2.40 for a client; ADR-0087), and the suite runs the git `scripts/git-pin.env` pins, never the machine's (`.claude/rules/gitlet.md`).
- **`testing`**, the standard library's, with no assertion framework: table tests where the cases vary, named tests where the reasoning does.

## Package Layout
- `cmd/crewlet/` — the one binary. Every command its switch dispatches must appear in `usage()`; a test asserts it (`.claude/rules/cli.md`).
- `internal/` — everything else (`internal/README.md`). Nothing is importable from outside the module: the engine has no stable Go API, only a CLI, a config format and a wire protocol.
- `dashboard/` — the dashboard's SOURCE (React 19, TypeScript, Vite). `make dashboard` builds it into `static/dashboard/`, `static/artifacts/` and `static/protocol/`, which are committed and NEVER hand-edited (`.claude/rules/dashboard.md`).
- `examples/` — the Nimbus example company, a working two-tier config. `docs/` — product documentation (docs.crewlet.ai). `skills/` — FOUNDER-facing authoring skills for an AI assistant (not `.claude/skills/`).
- `schema/` — GENERATED JSON Schema for both config tiers (`crewlet schema <tier>`; a test regenerates and compares): change the Go models, never the files.
- `scripts/` — the two vendor dev-loop bootstraps, the DCO gate, the git, Chromium and floor Node pins, and the Playwright tree's install (`.claude/rules/dependencies.md`).

## Checks and Tests
- **Before committing, ALWAYS run `make check`**, every gate CI runs on a pull request (`.claude/rules/testing.md` lists them). It needs GnuPG, `xz`, `zip`, `unzip`, `node` (with its npm), `python3`, and a prebuilt `golangci-lint` built with a Go whose language version is no older than `go.mod`'s. List unformatted files with `gofmt -l` over `go run ./internal/sourcetree/gofiles`, never `gofmt -l .`, which enters the nested checkouts under `.claude/worktrees/`. Repair with `make fmt` (`gofmt -s -w`) or `golangci-lint fmt` on that list (it also fixes import grouping), never plain `gofmt -w`, which cannot fix what the linter reports.
- **Run `make test` and `make test-solo`**, never a bare `go test ./...`, which runs the cluster-forming packages beside everything else and bypasses `internal/skipgate`; `go test ./internal/foo/` is a fine loop for one package. Every package runs under the race detector with `-count=1`. Packages that stand up a multi-member broker run alone in `make test-solo`, so a run of `make test` by itself has NOT exercised the fleet.
- **A skip is not a pass**: both test targets fail on a skip not declared in `internal/skipgate/allowed.go`. `internal/store`'s capability cases skip DELIBERATELY, and that is the mechanism rather than a gap: a feature Turso announces but does not reach Go yet turns into a passing test the day it lands.
- **The Makefile is the command CI runs.** The two test jobs call `make test` and `make test-solo`, so `GOTEST`, `GOTESTBUILD` and `GOTESTRUN` change CI; every other job inlines its own copy of its target, and nothing checks they agree. Change a target and its `ci.yml` step in the same commit, and give a new target its `## ` help line.
- **Every subsystem needs tests, and a test names the invariant it protects**, not the function it calls. Tests never call real LLM APIs (`internal/providers` has the fakes). A fixed wait decides nothing: a claim rests on a signal, never on time having passed (`internal/fixedwait`). **A test that cannot fail is worse than none**: break what you wrote on purpose and confirm the suite goes red.

## Documentation
Every change to code, config or behaviour ships its docs; stale docs are worse than none. A change to a public API, config format, CLI command, data model or behaviour updates its `docs/` pages; a new feature gets a page or a section; a renamed or removed name is fixed everywhere (grep it); an architecture change updates `docs/concepts/`, and a quickstart-affecting one `docs/getting-started/quickstart.md`. In doubt, update. `.claude/rules/docs.md` has how pages are written and held together.

**Write concisely**: docs, comments, `CONTRIBUTING.md` and these instructions alike. Say each thing once, where it is decided, in the fewest plain words that keep it exact. No padding; no restating, except a rule this file or `.claude/` mirrors from a root-level file (both change together); no history, which the commit, the pull request and the issue keep. Every reader pays for every word, and most readers here are agents that pay again on every later request.

## crewlet-operator, Releases and Dependencies
- **`crewlet/crewlet-operator`** (public, Elastic License 2.0) runs Crewlet companies from Kubernetes custom resources and consumes this engine's contract. Its suites run this repository's `main` as `ghcr.io/crewlet/crewlet:main`, never a pin, so an engine change it has not followed turns its next run red. A change to anything it renders, calls, copies, runs or links needs its companion change there, delivered with this one. The summary and the pull request description link it, or say in one line why there is none (`crewlet-operator: none — internal to the turn loop`); most changes need none and must not get one. `.claude/rules/operator.md` has the surfaces and the rules.
- **The tag is the version**: goreleaser stamps it into `internal/version.value` at link time, and no literal version constant is added back. The minor number moves for features, the patch number for fixes. `RELEASING.md` is the runbook; `.claude/rules/build-and-release.md` has the rest.
- **Pick the newest release, then pin it exactly**: found in the registry, not memory, written as a literal (`4.2.4`), never `latest` or `@main`; a version held back on purpose carries its reason at the pin. The shipped examples float (`@latest` at most), except a server a bundled tool skill triggers on by tool name, and so do the tool versions a workflow names in `with:`, which Dependabot never bumps (`ci.yml`'s `golangci-lint` job lists them). A tool server a docs page, a skill or the curated MCP catalogue launches is held to the release `internal/config/toolservers_test.go` and its catalogue entry record. A new dependency surface ships with its `updates:` entry in `.github/dependabot.yml`. Dependabot, its workflows and the git, Chromium and floor Node pins are in `.claude/rules/dependencies.md`.
