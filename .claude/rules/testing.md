# Gates and Tests
`CLAUDE.md`'s "Checks and Tests" has what every change needs; this is the rest.

## What `make check` runs
`make check` is every gate CI runs on a pull request:
- `gofmt -l` over `go run ./internal/sourcetree/gofiles` — never `gofmt -l .`, which enters every nested checkout under `.claude/worktrees/`. It is one of TWO formatting gates, at two standards: `golangci-lint run` enables the `gofmt` formatter with `simplify` on, and `goimports` beside it, so a redundant composite-literal type passes this one and fails that one. Repair with `make fmt` (`gofmt -s -w` over the same list, which clears both gofmt standards) or `golangci-lint fmt` handed the captured list (which also fixes the import grouping) — never plain `gofmt -w`, which cannot fix what the linter reports. `CONTRIBUTING.md` says the same.
- `go mod tidy -diff` (`make tidy` applies the patch)
- `scripts/check-signoff.sh` and its suite `scripts/check-signoff_test.sh`
- `scripts/git-pin_test.sh` (`make git-test`) — the git recipe's and the weekly pin check's own suite; it reads no network, builds no git and needs GnuPG
- `scripts/chromium-pin_test.sh` (`make chromium-test`) — the Chromium recipe's and the weekly pin check's own suite; it reads no network, fetches no Chromium and needs `zip` and `unzip`
- `go vet ./...` — the only vet: both test targets run `go test -vet=off`
- `golangci-lint run` — use a prebuilt release; one built with a Go older than `go.mod`'s refuses the module
- `go build ./...`, and a cross-compile of every release target
- the three dashboard gates: `dashboard-lint` (`npm run format:check`), `dashboard-check` (rebuild and diff the committed bundle) and `dashboard-test` (`npm run typecheck && npm test && npm run test:layout`, the last in a headless browser)
- `make git` — the pinned gits, built once a machine; both test targets depend on it, so no gate runs the machine's own git
- `make chromium` — the pinned Chromiums, the newest and the floor of the CDP client (`internal/browser/cdp.MinMajor`), fetched once a machine; both test targets depend on it and name the two builds, so no gate drives the machine's own Chrome
- `make test`, then `make test-solo`

**Every package runs under the race detector with `-count=1`**, so a cached pass never answers for a change; `make test-norace` is a faster loop and not a gate. **The packages that stand up a multi-member broker run alone**, in `make test-solo` at `-p 1`, because N embedded NATS servers in one CPU-starved process leave replicated creates unanswered. Which packages those are is COMPUTED, never listed: a package declares it by importing `internal/solo` from its `TestMain`, and `internal/solo`'s roster guard fails the build in both directions. Never reach for a build tag, `-short`, `-skip` or a custom flag instead: each fails silently (`go doc ./internal/solo` has the measurements). `make check` runs both halves, so nothing is uncovered, but a run of `make test` by itself has NOT exercised the fleet. In CI each half runs on several runners at once: `test plan` deals both into shards by measured duration and proves every package lands in exactly one, each `test (race) I/N` leg runs `make test` and each `end-to-end gates I/N` leg runs `make test-solo` with `TEST_SHARD`/`TEST_WEIGHTS`/`TEST_TIMINGS` (longest packages first, never fewer packages; a solo shard is its own machine, so `-p 1` still holds per runner), and the aggregate jobs named `test (race)` and `end-to-end gates` are the required checks.

**A skip is not a pass.** Both test targets pipe `go test -json` through `internal/skipgate`, which fails the run on a skip not declared in `internal/skipgate/allowed.go`, each entry with a reason and a `When` (`Always`, also reported once it stops firing, or `Environment`). `internal/store`'s capability cases skip DELIBERATELY, and that is the mechanism rather than a gap: a feature Turso announces but does not reach Go yet turns into a passing test the day it lands. `node` runs three suites: the dashboard's own (through `npm`, which ships with it), `internal/e2e`'s client replay (in `make test-solo`) and `internal/sandbox/executor`'s probes of the two OpenCode plugins the engine embeds, the notes plugin and the skill-load plugin (in `make test`), and every make target that runs one refuses to start without it. What `make check` does not cover (`make snapshot`) it prints when it passes.

## Writing tests
- Test files sit beside what they cover, a test file that is not Go included: the dashboard's Vitest suites beside their modules in `dashboard/src`, `internal/e2e/replay.mjs` beside the `golden_test.go` that runs it, and `internal/sandbox/executor/opencode_steer_probe.mjs` and `opencode_skills_probe.mjs` beside the `opencode_steer_test.go` and `opencode_skills_test.go` that run them. There is no top-level `tests/` tree
- **A program the suite needs is found through `internal/prereqtest`** — `OnPath` for one on `PATH`, `Named` for one a variable names — which fails the case under the make targets that run the suite (`CREWLET_REQUIRE_PREREQUISITES=1`, the Makefile's `REQUIRED`) and skips it only in a bare `go test` outside make, in the same words; never through a skip of its own, a `skipgate` entry or a requirement variable of its own, each a second copy of the one rule. A program no make target requires (a container runtime) keeps its `Environment` entry
- **A contract with more than one implementation gets ONE suite** (`queuetest`, `coordtest`, `storetest`, `scheduletest`, `sandboxtest`), which every backend runs, the memory twins included
- **A store on a fresh path starts from the migrated image** — `storetest.OpenNode`, `storetest.OpenEstate`, or `storetest.Seed` before an engine boots on it. Only a test whose subject is migration opens a fresh file with `store.OpenNode`
- **A test broker declares its size** — `brokertest.StoreIn` for a node's stream (with `brokertest.GitletCacheIn` beside it where Gitlet runs), `StoreMaxBytes: brokertest.StoreMaxBytes` for a broker opened directly, `JetStreamMaxStore: brokertest.StoreMaxBytes` for a server a case builds from nats-server's own options (`max_file_store` in a configuration it writes), `externaltest.Start` for an external one. Left unset, the limit is three quarters of the runner's free disk, so the case passes or fails on the machine — and a test binary refuses to start such a broker (`jetstream.ErrUndeclaredSize`) or build Gitlet with such a cache (`engine.ErrUndeclaredCodeCache`), whatever route the case took to it, and a test's node refuses to open on an external broker whose account states no limit (`engine.ErrUndeclaredBrokerLimit`), since a node reads the account's limit and never the server's cap, while `brokertest`'s `TestEveryNATSServerATestBuildsDeclaresItsSize` fails a server built from nats-server's options that leaves it unset. Only a case whose subject is the derived limit leaves it unset, under `jetstream.SizedByTheDisk` or `engine.SizedByTheMachine`, saying why
- **A test broker keeps its store in `brokertest.TempDir`**, never `t.TempDir` — a node fixture's `brokertest.StoreIn` directory, a broker a case opens or starts itself, and a server built from nats-server's options alike. A stopped nats-server can land a consumer's last state flush after `Shutdown` and `WaitForShutdown` return (its stop polls for the flush for 100 ms rather than joining it), and `t.TempDir`'s single removal then fails the case on a file it never wrote; `brokertest.TempDir`'s removal tries again while, and only while, the directory comes back not empty, a bounded number of times, and goes once a pinned nats-server joins the flush loop. So a test binary refuses to start an embedded broker whose store lies in no `brokertest.TempDir` (`jetstream.ErrStoreOutsideTempDir`, told by the name it gives its directories), whatever route the case took to it, while `brokertest`'s `TestEveryNATSServerATestBuildsKeepsItsStoreInATempDir` fails a server built from nats-server's options whose store is a test's own temporary directory (a `testing.TB`'s `TempDir`, or `os.MkdirTemp` in a test file). A store directory only validated, with no broker started on it, may stay a `t.TempDir`
- **A case that STARTS an engine never runs below `internal/engine`'s `startedLeaseTTL`**, which is `config.MinLeaseTTL` and the floor `engine.New` holds every bootstrap to anyway. The lease TTL is also the seat watchdog's threshold, and once a host goes that long without a beat the watchdog ends the PROCESS with status 75 — in a test, the whole binary and every case running in it, which no assertion reports: two cases at three seconds sat one loaded runner from it, and the one meant to catch a start context cancelling the renewer could never fail, because the watchdog ended the binary first. So a case reads the renew or the deadline it is about off the host or its store (`seat.Host.MayStart`, a lease's deadline) rather than waiting for a lease to lapse, and a case whose subject is a fraction of a shorter TTL builds an `Engine` literal that starts no seat host
- **What a plan says is read in `storetest`, once.** The pinned driver may rewrite a correlated scalar subquery that selects one aggregate into a join against its WHOLE child table grouped by the correlation columns, chosen by its cost guess over a database nobody has ANALYZEd rather than by any line of the statement, so `storetest.Decorrelated` is the one check for it — the `scalar_subquery_<n>` operand the rewrite produces, never the `ephemeral_subquery_` index a FROM-clause subquery is joined through — held to the driver in both directions, so a driver bump that renames or stops the rewrite fails there before it blinds a gate. It sits beside the one VOCABULARY every plan gate reads a plan through, over either estate's handle (`Handle`: the node's own file as much as the replicated estate) — `PlanTree`, `Plan` and `Details`; `IndexesIn`, `Seeks`, `Walks`, `Sorts` and `ScansHeap`; `IndexesOn`; and `StatementLiterals`, the walk of the module's source a gate's completeness check makes, which fails when it read nothing outside the gate's own package — because two copies of how a plan is spelled are two gates a driver bump blinds one at a time, and a gate's private reading had already planned a copy of the statement it held: so a walk of every Go file of the module, tests included, refuses an `EXPLAIN QUERY PLAN` spelled in a literal anywhere but `storetest/plan.go`, package `store`'s own files alone exempt, since they cannot import the package that imports them; and the tracker's and the knowledge base's index gates, search's vector and lexical gates and the chat prune's room read each refuse what `Decorrelated` flags
- **A case that drives Chromium drives the pins** — `internal/browser/chromiumtest` hands it the two builds `scripts/chromium-pin.env` pins and runs it on both (`chromiumtest.Each`), or on the newest alone where its doc says why the floor adds nothing to its claim (`TestAScreenshotSizedMessageCrossesBothTransports`), never the machine's own Chrome, whose version nothing pins; a missing build fails it under every make target that runs the whole suite (`test`, `test-solo`, `test-norace`), as a missing git does
- Use the fakes in `internal/providers`; tests never call real LLM APIs. A phase that offers tools plays its model as a scripted harness run over the REAL tool session (`internal/providers/llm/llmtest`), never by calling the dispatcher around it
- **A fixed wait decides nothing** — a test claim rests on a signal, never on wall-clock time having passed: `internal/fixedwait` refuses a new `time.Sleep`, `After`, `AfterFunc`, `NewTimer`, `NewTicker` or `Tick`, and a new `time.Since`, `time.Until`, or `time.Time`'s `Sub`, `Before`, `After` or `Compare` (told by its receiver's type; never `Equal`), in test code outside a synctest bubble, a verified `//fixedwait:bubble` helper or a marker (`//fixedwait:liveness`, `simulated <reason>` or `bench` on a wait, `measure <reason>` on an elapsed reading, `stated <reason>` on a `Sub`, `Before`, `After` or `Compare` between instants no wall clock separates, never two independent readings of the wall clock), and its inventory only shrinks, each shape to its own count (`CONTRIBUTING.md`, "A fixed wait decides nothing"; `go doc ./internal/fixedwait`)
