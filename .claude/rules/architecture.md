# Architecture Reference
The implementation follows `docs/concepts/`. Its subsystems:
1. **Event Queue** — durable pub/sub behind one contract: embedded NATS JetStream by default, clustered members or an external cluster for a fleet, an in-memory twin for tests
2. **Organization Model** — the hierarchy is the execution graph: `roles:` and `units:` in the company document, applied with every revision. A seat's handle and a unit's key are its identity, minted on every write, never changed in place
3. **Agent Runtime** — queue-driven seats. A two-stage turn whose executor is the seat's harness's own run in a box, detached: the turn parks at launch and the same turn resumes on the run's collection, for the engine's delivery check and the reviewer. A tool loop runs every other phase as harness runs of the harness's own loop and decides every call the harness makes over MCP
4. **Worklet**: the engine's own work tracker, `statelog`'s first domain; a company on an external PM tool sets `tracker.backend` to it and the engine mirrors nothing. Hand-offs are bounded on the item (`reassignments`), not by the delegation depth cap
5. **Decision Framework** — DACI stays behavioural guidance. The engine records only a structured ask on a work item (`adr/0023`), enforcing only its shape, that a choice names one of its options, and a promised `inform`
6. **Knowledge System**: Doclet, the company's pages (`statelog`'s third domain), searched by keyword (BM25 over the engine's own index; Turso has no fts5), semantically (two-stage 1-bit retrieval: a replicated inverted file over sign codes, then an exact rerank) or `hybrid` by default (both fused by reciprocal rank fusion, k = 60). Embeddings are a domain computed once by a fleet duty. Confluence is the other backend, one per company. Plus each agent's diary. Chat is deliberately outside this corpus and the vector budget, with its own inverted list and no semantic half: a year at the declared census needs several times the whole supported vector corpus, and Doclet's own embeddings would pay for it (ADR-0071)
7. **Communication** — chat and ephemeral A2A channels. Chat is a backend axis like the tracker's and the knowledge base's: `chat.backend` is `chatlet` (the engine's own, `internal/chatlet`; the default when a company declares no vendor chat surface), `vendor` (Mattermost or Slack) or `none`. Chatlet beside a vendor is refused: with two live chat homes a person replies where the agents aren't reading. `vendor` names a posture, not a product, because Mattermost and Slack legitimately run together. On the engine's own chat everybody speaks as a seat (an agent as itself; a person as the human seat they hold, with the `chatlet` app), so a credential acting as itself reads no room, and a seat's read state, rooms and conversations pass to whoever holds it next. The eight surfaces are `integration.Kinds`
8. **Notification Service** — a queue-based spine, the vendors on top
9. **Provider Layer** — every model is a harness (one login or key per entry; a spent plan sits its entry out), handed a phase's tools as one MCP server and read back through its own record of each request, behind a fallback chain: per call on the engine host, continuing from what the phase already did, and per launch for a seat's executor, which takes the chain's first member whose harness has an in-box runner (Claude Code, Codex, Gemini CLI, Qwen Code, OpenCode, Cursor Agent, Copilot, Grok Build, Muse Code, Kimi Code, Hermes Agent or Pi) not sitting out. Embeddings use the OpenAI SDK
10. **Store** — each node's own embedded Turso files: its NODE file and, on a data node, the whole REPLICATED estate beside it (two files, because a snapshot copies one); a node without `data` keeps a scratch file. Spend and turn history is the replicated `usage` domain, kept 181 days (ADR-0020); turn detail stays 30 days in each data node's event log, read from every node at query time (ADR-0021)
11. **Coordination** — TTL leases with a fencing epoch, plus the fleet's shared counters, ledgers and sealed credentials. A token budget is counted per calendar window and never reset by hand (ADR-0019)
12. **Seat Ownership** — which node runs which seat, converging without a coordinator
13. **Tool Registry** — builtins, MCP tools and A2A tools, each recording its origin
14. **Tool Skills** — knowledge-base-sourced prompt fragments injected per phase
15. **Code Sandbox** — every agent seat's executor runs in a box in the cell its launching `providers.llm` entry's `run_in` names (`direct` on the engine host, or `container`), else `providers.sandbox.default_run_in`, so `providers.sandbox` is required once a company has an agent seat and a model. A seat holds up to its `sandbox.max_concurrent_runs` of runs (two by default), one per conversation, and starts no other turn at that cap; below it, a message that waits on one of its runs is set aside on the inbox until that run leaves, and the rest start beside them (ADR-0169). A message from the run's own requester about its work is handed to the run (ADR-0167), a run can park on a person's question, and every box is driven by the node that launched it (ADR-0065)
16. **API + Dashboard** — one wiring, always in the engine's process: the socket carries the live state and its questions, REST carries every write, and the dashboard writes as the principal its session resolves to (`/operator/act`, ADR-0024)
17. **Scheduler** — role- and unit-scoped cron work with at-most-once delivery, catchup and a wall-clock cap
18. **Control Plane** — the config activation pointer and per-node apply status; lag alone never sheds
19. **State Log** — one ordered stream per domain is the write-ahead log, N identical SQL copies are the state, and the checkpoint commits in the same transaction as the rows. One write authority (take one snapshot, decide inside it, publish, let the broker arbitrate), three write outcomes, four read levels. Fourteen domains: the tracker, the vectors, the knowledge base, the identity estate, each data node's usage, the artifacts, their datastore, the Dashboard Assistant's conversations, chat, the seats' executor sessions, Gitlet's repositories, the seats' access history, the atlas (ADR-0126) and the Advisor's findings. Each domain is a site in several per-domain lists that fail silently when a new domain is added and one is missed
20. **Identity Estate** — people, credentials, invitations and sessions as `statelog`'s fourth domain. Uniqueness is arbitrated on one directory subject, never indexed, and a person holds one human seat for as long as they exist (ADR-0032)
21. **Estate Topology** — a node holds the estate (`data`, which `ingress` and `workers` require) or reaches it through one that does, over the estate router, every request signed under the fleet keyring (ADR-0025, ADR-0031). A file is a replicated row naming an object in the fleet's one object store (ADR-0026)
22. **Gitlet** — the engine's own git host:
    - **Storage and access** — repositories are rows on the code log, each push's pack bundle is one object in the object store, and every Gitlet node keeps a disposable cache of each repository derived from the rows (ADR-0084). Persons clone and push over HTTPS with their own token: git is one more way a person acts (ADR-0085)
    - **Seats** — read through the `code_*` tools, server-side on the repository's home Gitlet node, with grants derived from the chart (ADR-0088, ADR-0089); commit through engine-built pushes (ADR-0092); manage repositories through tools
    - **Changes** (ADR-0097) — a change (one branch proposed into another) is rows on its repository's subject, decided by the committer beside its pushes; its reviews, findings and comments are a conversation on the change's own subject, decided by the change writer. Every record of a change wakes the seats it concerns from the code log under `crewlet-code-feed` and leaves a person an inbox notice; the woken turn is charged to the change's work item, and the change carries no spend
    - **Code search** — a code search of several repositories is one signed scatter over the Gitlet nodes that hold them, each searching its repositories as the asker through its own reads (a trigram index of an indexed repository's default branch on its first two Gitlet nodes, git grep otherwise), merged exactly and naming every repository it did not search
    - **Mirrors** — a repository's home Gitlet node imports, pull-mirrors or push-mirrors it over one outbound HTTPS dial held to public addresses. A push mirror publishes each protected branch at its green commit (`code_green`), never its tip, as a named seat's own identity at the other forge. Its failures are the home's in-memory state, which `code_mirror_failing` raises
