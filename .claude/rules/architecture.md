# Architecture Reference
The implementation follows `docs/concepts/`. Its subsystems:
1. **Event Queue** — durable pub/sub behind one contract: an embedded NATS JetStream by default, clustered members or an external cluster for a fleet, an in-memory twin for tests
2. **Organization Model** — the hierarchy is the execution graph: `roles:` and `units:` in the company document, applied with every revision; a seat's handle and a unit's key are its identity, minted on every write and never changed in place
3. **Agent Runtime** — queue-driven seats; a two-stage turn whose executor is the seat's harness's own run in a box, detached (the turn parks at launch and the same turn resumes on the run's collection, for the engine's delivery check and the reviewer); and a tool loop that runs every other phase as harness runs of the harness's own loop and decides every call the harness makes over MCP
4. **Worklet**: the engine's own work tracker, `statelog`'s first domain; a company on an external PM tool sets `tracker.backend` to it and the engine mirrors nothing. Hand-offs are bounded on the item (`reassignments`), not by the delegation depth cap
5. **Decision Framework** — DACI stays behavioural guidance; what the engine records is a structured ask on a work item (`adr/0023`), enforcing only its shape, that a choice names one of its options, and a promised `inform`
6. **Knowledge System**: Doclet, the company's pages (`statelog`'s third domain), searched by keyword (BM25 over the engine's own index; Turso has no fts5), semantically (two-stage 1-bit retrieval: a replicated inverted file over sign codes, then an exact rerank) or `hybrid` by default (the two fused by reciprocal rank fusion at k = 60). Embeddings are a domain computed once by a fleet duty. Confluence is the other backend, one per company. Plus each agent's diary. The company's chat is deliberately outside this corpus and the vector budget: it has its own inverted list and no semantic half, because a year at the declared census needs several times the whole supported vector corpus, and Doclet's own embeddings would pay for it (ADR-0071)
7. **Communication** — chat and ephemeral A2A channels. Chat is a backend axis like the tracker's and the knowledge base's: `chat.backend` is `chatlet` (the engine's own, `internal/chatlet`, the default for a company that declares no vendor chat surface), `vendor` (Mattermost or Slack) or `none`, and Chatlet beside a vendor is refused, because with two live chat homes a person replies where the agents aren't reading. `vendor` names a posture rather than a product, because Mattermost and Slack legitimately run together. On the engine's own chat everybody speaks as a seat: an agent as itself, a person as the human seat they hold (the `chatlet` app), so a credential acting as itself reads no room, and a seat's read state, rooms and conversations pass to whoever holds it next; the eight surfaces are `integration.Kinds`
8. **Notification Service** — a queue-based spine, the vendors on top
9. **Provider Layer** — every model a harness (one login or key per entry, a spent plan sitting its entry out), handed a phase's tools as one MCP server and read back through its own record of each request, behind a fallback chain: per call on the engine host, continuing from what the phase already did, and per launch for a seat's executor, which takes the chain's first Claude Code or OpenCode member not sitting out; embeddings on the OpenAI SDK
10. **Store** — each node's own embedded Turso files: its NODE file and, on a data node, the whole REPLICATED estate beside it (two files, because a snapshot copies one); a node without `data` keeps a scratch file. Spend and turn history is the replicated `usage` domain, kept 181 days (ADR-0020); turn detail stays 30 days in each data node's event log and is read from every node at query time (ADR-0021)
11. **Coordination** — TTL leases with a fencing epoch, plus the fleet's shared counters, ledgers and sealed credentials; a token budget is counted per calendar window and never reset by hand (ADR-0019)
12. **Seat Ownership** — which node runs which seat, converging without a coordinator
13. **Tool Registry** — builtins, MCP tools and A2A tools, each recording its origin
14. **Tool Skills** — knowledge-base-sourced prompt fragments injected per phase
15. **Code Sandbox** — where every agent seat's executor runs: a box in the cell its launching `providers.llm` entry's `run_in` names (`direct` on the engine host, `container`, or `e2b`), else `providers.sandbox.default_run_in`, so `providers.sandbox` is required once a company has an agent seat and a model; the seat takes no other work while its run works, a run can park on a person's question, and a `direct` or `container` box is driven by the node that launched it (ADR-0065)
16. **API + Dashboard** — one wiring, always in the engine's process; the socket carries the live state and its questions, REST carries every write, and the dashboard writes as the principal its session resolves to (`/operator/act`, ADR-0024)
17. **Scheduler** — role- and unit-scoped cron work with at-most-once delivery, catchup and a wall-clock cap
18. **Control Plane** — the config activation pointer and per-node apply status; lag alone never sheds
19. **State Log** — one ordered stream per domain is the write-ahead log, N identical SQL copies are the state, and the checkpoint commits in the same transaction as the rows; one write authority (take one snapshot, decide inside it, publish, let the broker arbitrate), three write outcomes, four read levels. Thirteen domains now (the tracker, the vectors, the knowledge base, the identity estate, each data node's usage, the artifacts, their datastore, the Dashboard Assistant's conversations, chat, the seats' executor sessions, Gitlet's repositories, the seats' access history and the atlas, ADR-0126), and each is a site in several per-domain lists that fail silently when a fourteenth is added and one is missed
20. **Identity Estate** — people, credentials, invitations and sessions as `statelog`'s fourth domain; uniqueness is arbitrated on one directory subject, never indexed, and a person holds one human seat for as long as they exist (ADR-0032)
21. **Estate Topology** — a node holds the estate (`data`, which `ingress` and `workers` require) or reaches it through one that does, over the estate router, every request signed under the fleet keyring (ADR-0025, ADR-0031); a file is a replicated row naming an object in the fleet's one object store (ADR-0026)
22. **Gitlet** — the engine's own git host: the company's git repositories as rows on the code log, each push's pack bundle one object in the object store, a disposable cache of each repository on every Gitlet node derived from the rows, and persons cloning and pushing over HTTPS with their own token — git, one more way a person acts (ADR-0084, ADR-0085); seats read it through the `code_*` tools, server-side on the repository's home Gitlet node, with grants derived from the chart (ADR-0088, ADR-0089); seats commit through engine-built pushes (ADR-0092) and manage repositories through tools; a change — one branch proposed into another — is rows on its repository's subject decided by the committer beside its pushes, its reviews, findings and comments a conversation on the change's own subject decided by the change writer, and every record of it wakes the seats it concerns from the code log under `crewlet-code-feed` and leaves a person an inbox notice, the woken turn charged to the change's work item and the change carrying no spend (ADR-0097); a code search of several repositories is one signed scatter over the Gitlet nodes that hold them, each searching its repositories as the asker through its own reads (a trigram index of an indexed repository's default branch on its first two Gitlet nodes, git grep otherwise), merged exactly and naming every repository it did not search; a repository is imported, pull-mirrored or push-mirrored by its home Gitlet node over one outbound HTTPS dial held to public addresses, a push mirror publishing each protected branch at its green commit (`code_green`), never its tip, as a named seat's own identity at the other forge, its failures the home's in-memory state that `code_mirror_failing` raises
